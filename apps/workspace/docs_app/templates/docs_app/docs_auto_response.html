Auto-Response

Automatically answer Claude Code CLI prompts — permission requests, idle states, and more.

Overview

When Claude Code runs in the console, it periodically asks for permission (Y/N or Y/Y/N prompts) and enters waiting/thinking states. Auto-Response detects these states and sends pre-configured responses automatically, so you can work hands-free. 

Claude State        →  Auto-Response
─────────────────────────────────────
Y/N prompt          →  "1" (Allow)
Y/Y/N prompt        →  "2" (Allow always)
Waiting/thinking    →  "/speak-signature"
Suggestion prompt   →  Enter (accept)

How It Works

State Detection

The system polls the terminal buffer at a configurable interval (default 1.5s) and pattern-matches against known Claude Code UI states:

State Pattern Default Response
y_n 2-option permission prompt (Allow / Deny) 1 (Allow)
y_y_n 3-option permission prompt (Allow once / Always / Deny) 2 (Allow always)
waiting Claude is thinking or idle /speak-signature
suggestion Claude suggests an action (Enter) — accepts suggestion

Response Flow

  1. Detect — poll terminal buffer for known patterns
  2. Throttle — skip if same state responded to recently
  3. Y/N upgrade check — wait 1s to see if Y/N upgrades to Y/Y/N
  4. Send — write response text to terminal
  5. Verify — re-check state after 2s to confirm response registered
  6. Retry — if state unchanged, retry (permission prompts: 1 retry max)

Configuration

Click the gear icon in the console toolbar to open the config popover. Settings are saved to your account and persist across sessions.

Response Commands

Setting Description Default
Waiting Command sent when Claude is thinking or idle. Any valid Claude Code slash command or text. /speak-signature
Y/N Response for 2-option permission prompts 1 (Allow)
Y/Y/N Response for 3-option permission prompts 2 (Allow always)

Timing & Safety

Setting Description Default
Interval How often to check for prompts 1.5s
Safety Burst rate limiting preset Normal

The /speak Command

/speak is a Claude Code slash command that triggers text-to-speech via the audio_speak MCP tool. When Claude receives /speak, it summarizes its current progress and speaks it aloud through your browser.

Command Behavior
/speak Claude speaks a progress summary
/speak-signature Same as /speak but appends "— Claude" signature
You can set the Waiting response to any command — for example, /speak, /progress, or even a custom prompt like please continue working.

Safety Features

Feature Description
Burst Rate Limiting Max 10 responses per 3s window (configurable via Safety preset)
Same-State Throttle Min 1.5s between responses to the same state
Idle-Loop Detection Suppresses waiting responses after 3 consecutive sends without real work in between (30s threshold)
Stuck-State Watchdog Forces re-send if a state persists for >15s unchanged
Content Hash Skip Skips send if terminal buffer content hasn't changed
Y/N Upgrade Detection Waits 1s after Y/N to check if options expand to Y/Y/N

Emacs Integration

The browser auto-response system is a port of emacs-claude-code (ecc-auto-response.el). Emacs users can configure auto-response via: 

(setq --ecc-auto-response-responses
  '((:y/n . "1")
    (:y/y/n . "2")
    (:waiting . "/speak-signature")
    (:initial-waiting . "/understand-guidelines")))

Both systems share the same state detection logic and safety features. The browser version persists settings to your SciTeX account; the Emacs version uses Emacs custom variables.
