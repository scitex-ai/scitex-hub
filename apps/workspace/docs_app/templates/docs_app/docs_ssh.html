SSH Access

Connect to your SciTeX Cloud workspace via SSH for terminal access, file editing, and remote development.

Quick Start

Development
ssh -p 2200 your-username@127.0.0.1
Production
ssh your-username@ssh.scitex.ai

SSH Key Registration

SSH public key authentication is required for shell access. Register your key using one of these methods:

Method 1: Web UI (Recommended)
  1. Go to Account Settings → SSH Keys
  2. Paste your public key (e.g., contents of ~/.ssh/id_ed25519.pub)
  3. Click "Add Key"
Method 2: ssh-copy-id 
# Development
ssh-copy-id -p 2200 your-username@127.0.0.1

# Production
ssh-copy-id your-username@ssh.scitex.ai

You'll be prompted for your SciTeX Cloud password. The gateway registers your key automatically.

Method 3: Interactive (Password SSH) 
# SSH with password — opens key registration prompt
ssh -p 2200 your-username@127.0.0.1

Password authentication opens an interactive session where you can paste your public key directly.

Method 4: SciTeX CLI 
scitex-hub ssh-copy-id --env dev
scitex cloud ssh-copy-id --env dev

Editor Integration

Emacs TRAMP 
;; Development (port 2200)
C-x C-f /ssh:your-username@127.0.0.1#2200:/home/your-username/

;; Production
C-x C-f /ssh:your-username@ssh.scitex.ai:/home/your-username/
VS Code Remote SSH

Add to ~/.ssh/config: 

# Development
Host scitex-dev
    HostName 127.0.0.1
    Port 2200
    User your-username

# Production
Host scitex
    HostName ssh.scitex.ai
    User your-username

Then use "Remote-SSH: Connect to Host" and select scitex-dev or scitex.

Cloudflare Tunnel (Production)

Production SSH goes through Cloudflare Access. Install cloudflared and add to ~/.ssh/config: 

Host ssh.scitex.ai
    ProxyCommand cloudflared access ssh --hostname %h
    User your-username

Install cloudflared: brew install cloudflare/cloudflare/cloudflared (macOS) or see Cloudflare docs.

Troubleshooting

  • Register your SSH key first (see Key Registration above)
  • Check your key is listed: Account Settings
  • Try with verbose: ssh -vvv -p 2200 user@host

The server's host key may have changed after a restart. Clear the old entry:

ssh-keygen -R "[127.0.0.1]:2200"

The terminal broker service may not be running. Check:

# Check broker status
ls -la /tmp/scitex-terminal-broker.sock

# Check SLURM
scontrol ping

Contact your administrator if the broker is not running.

Log into the web interface first to create your default project, then try SSH again.

CLI Reference 

# Connect via SSH
scitex-hub ssh --env dev
scitex cloud ssh --env dev

# Register SSH key
scitex-hub ssh-copy-id --env dev
scitex cloud ssh-copy-id --env dev

# Options
scitex-hub ssh --user myuser --port 2200
scitex-hub ssh -- -L 8888:localhost:8888  # Port forwarding
