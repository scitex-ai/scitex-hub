CSRF Utilities

Helpers for reading Django's CSRF token from multiple DOM sources and building request headers.

Import 

import { getCsrfToken, createHeadersWithCsrf } from '@shared/utils/csrf';

Usage 

// Bare token — attach manually
const token = getCsrfToken();
fetch('/api/action/', {
  method: 'POST',
  headers: { 'X-CSRFToken': token, 'Content-Type': 'application/json' },
  body: JSON.stringify({ key: 'value' }),
});

// Headers object — convenience wrapper
const headers = createHeadersWithCsrf({ 'Accept': 'application/json' });
fetch('/api/action/', { method: 'POST', headers, body: JSON.stringify(data) });

// Prefer apiClient for everyday requests — CSRF is automatic there
import { apiClient } from '@shared/utils/api';
await apiClient.post('/api/action/', data);

API Reference

Function Returns Description
getCsrfToken() string Reads the CSRF token from the first available source in priority order: WRITER_CONFIG.csrfToken, SCHOLAR_CONFIG.csrfToken, [name=csrfmiddlewaretoken] form input, <meta name="csrf-token">, then the csrftoken cookie. Returns "" if none found.
createHeadersWithCsrf() Record<string, string> Returns a headers object pre-populated with Content-Type: application/json and X-CSRFToken. Pass additionalHeaders to merge extra entries.
Low-level utility: Prefer apiClient from @shared/utils/api for standard HTTP calls — it calls getCsrfToken() internally. Use these helpers only when calling fetch() directly.
