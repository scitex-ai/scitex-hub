CSS Scoping with data-mode

How to write module CSS that stays isolated and never leaks into shared panes or other apps.

The Scoping Rule

Every selector in a module's CSS file must start with [data-mode="yourmodule"]. This is the single mechanism that prevents cross-module style pollution. 

/* mymodule_app/static/mymodule_app/css/mymodule.css */

/* CORRECT — all rules scoped */
[data-mode="mymodule"] .panel { background: var(--bg-surface); }
[data-mode="mymodule"] .header { font-size: 13px; }
[data-mode="mymodule"] .btn-run { color: var(--app-accent-mymodule); }

/* WRONG — unscoped rules leak globally */
.panel { background: var(--bg-surface); }
.header { font-size: 13px; }

Naming Conventions

Item Convention Example
CSS file location apps/{name}_app/static/{name}_app/css/ apps/writer_app/static/writer_app/css/writer.css
Root selector [data-mode="{name}"] [data-mode="writer"]
data-mode value Lowercase, matches the app registry key exactly writer, scholar, console
Class names inside scope Short, no module prefix needed (scope provides namespacing) .toolbar, .pane-header, .sidebar-item
Workspace-specific overrides Use --workspace-* tokens, not raw colors var(--workspace-bg-primary)

Common Pitfalls

Problem Cause Fix
Styles apply in wrong module Selector missing [data-mode] prefix Wrap every rule in [data-mode="yourmodule"]
Accent color wrong in dark mode Hardcoded hex instead of token Use var(--app-accent-yourmodule)
Component looks broken in workspace Global component CSS overridden by workspace styles Add specificity with [data-mode="yourmodule"] prefix
data-mode not matching Value differs from registry name (e.g. "Writer" vs "writer") Must be lowercase and match the Python registry key exactly

Complete Module CSS Template 

/* apps/mymodule_app/static/mymodule_app/css/mymodule.css */

[data-mode="mymodule"] {
  /* Root-level CSS variables scoped to this module */
  --local-header-height: 36px;
}

[data-mode="mymodule"] .workspace-pane {
  background: var(--workspace-bg-primary);
  border: 1px solid var(--workspace-border-default);
}

[data-mode="mymodule"] .pane-header {
  height: var(--local-header-height);
  border-top: 2px solid var(--app-accent-mymodule);
  background: var(--app-accent-mymodule-tint);
  color: var(--text-primary);
}
The data-mode attribute is set by the workspace layout on the pane root element when a module is loaded. Shared panes (e.g. file browser, AI panel) do not carry a data-mode value — their styles live in static/shared/css/ and must not be overridden by module CSS.
