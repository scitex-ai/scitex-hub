CSS Design Tokens (Primitives)

Semantic CSS custom properties defined in static/shared/css/primitives/colors.css — use these in all component styles.

Text Tokens

Token Light value Dark value Use
--text-primary #333333 #e6edf3 Body text, headings, labels
--text-secondary #4a4a4a #c9d1d9 Secondary descriptions, subtitles
--text-muted #777777 #8b949e Placeholders, hints, metadata
--text-inverse #f8f7f5 #161b22 Text on dark/accent backgrounds
--text-color Alias for --text-primary Legacy compatibility alias

Background Tokens

Token Light value Dark value Use
--bg-page #faf9f7 #0d1117 Outermost page background
--bg-surface #f8f7f5 #161b22 Cards, panels, modals
--bg-muted #f3f2f0 #21262d Subtle inset areas, code backgrounds

Border & Status Tokens

Token Light value Dark value Use
--border-default #999999 #30363d Standard element borders
--border-muted #c0c0c0 #21262d Subtle dividers, secondary borders
--status-success #5a9a7e #4a9b7e Success messages, confirmations
--status-warning #b8956a #b8956a Warning alerts, cautions
--status-error #a67373 #a67373 Error states, destructive actions
--status-info #6b7280 #6b7280 Informational notices

Icon Size Tokens

Token Value Use
--icon-xs 12px Dense UI, badge icons
--icon-sm 14px Inline text icons
--icon-md 16px Default icon size
--icon-lg 20px Nav icons (default for --ui-nav-icon-size)
--icon-xl 24px Prominent icons
--icon-2xl 32px Hero / empty-state icons
Never use raw hex values in component CSS. Always reference a semantic token (e.g. var(--text-primary)) so the component automatically adapts to light and dark themes. Primitives prefixed with --_ are internal to colors.css and must not be used directly.
