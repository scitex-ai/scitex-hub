Create an App

Three ways to create a SciTeX app:

Web (/new/)

Navigate to /new/ and select App Template. The platform scaffolds the full boilerplate, creates a Gitea repo, and sets up the project in one step.

CLI

scitex-cloud app init .
scitex-cloud app init /path/to/my_app --name demo_app -l "Demo" -i "fas fa-flask"
scitex-cloud app init . --frontend react  # React+Vite+Zustand

AI-Assisted

Ask the AI in the Console or Chat panel: "Create a new workspace app called sample_tracker_app"

manifest.json Schema

Every app has a manifest.json — the single source of truth for metadata, dependencies, and configuration. Schema: scitex-app-manifest v1.0.0. 

{
  "$schema": "scitex-app-manifest",
  "$schema_version": "1.0.0",
  "name": "my_app",
  "label": "My App",
  "icon": "fas fa-puzzle-piece",
  "description": "What the app does",
  "version": "0.1.0",
  "license": "AGPL-3.0",
  "keyboard_shortcut": "",
  "order": 50,
  "accent_color": "",
  "ai_hint": "One-line description for AI agents",
  "allowed_extensions": [".csv", ".json"],
  "builtin": false,
  "dependencies": {
    "python": ["pandas>=2.0"],
    "system": [],
    "node": [],
    "r": [],
    "other": []
  },
  "container": null
}

All 10 builtin apps use this same schema. Registry loads from manifest.json files at startup.

Develop on Web

The primary development workflow is web-first. After creating your app:

  1. Your app appears as a sidebar tab in the workspace
  2. Edit code in the workspace file viewer or Console terminal
  3. Changes are live — templates reload on each request
  4. Context builders run inside Apptainer via dev_app_runner.py
Your project directory is mounted to /workspace inside the container with read-write access. You have full filesystem access via stx.io.

Local Development

For power users who prefer local development:

# Install the CLI
pip install scitex-cloud

# Show dev instructions for an app
scitex-cloud app dev .

# Validate before submitting
scitex-cloud app validate .

Storage Options

Method Best For Access
stx.io Project files (CSV, JSON, images) Read/write at /workspace
SQLite Single-user structured data /workspace/data.db
PostgreSQL Multi-user, concurrent access Via .env credentials

Configuration lives in the project root (.env, .bashrc), user-managed. No restrictions on storage choice.

Environment Variables

Variable Description
SCITEX_CURRENT_APP Name of the currently active app (set automatically)
SCITEX_CLOUD_URL Server URL for API calls

Use in .bashrc for app-specific setup: 

if [ "$SCITEX_CURRENT_APP" = "writer" ]; then
    export TEXINPUTS=".:./tex//:"
fi

Dependencies

Declare dependencies in manifest.json under dependencies. Supports five categories:

Type Tool Example
python pip ["numpy>=1.24", "scipy"]
system apt ["texlive-full", "ghostscript"]
node npm ["react>=18"]
r CRAN ["ggplot2", "dplyr"]
other Manual ["CUDA 12.0"] 
# Check dependencies
scitex-cloud app check-deps .

# Install Python dependencies
scitex-cloud app install-deps . --type python

Per-App Containers

Apps run in the shared Apptainer container by default. For apps with special requirements, set "container" in manifest.json to a .def or .sif file: 

{
  "container": "my_app.def"
}

# Build the container
scitex-cloud app build-container .

The .sif image overrides the user's default container for this app only.

User Preferences API

Per-user persistent preferences stored at ~/.scitex/cloud/apps/prefs.json. No database required.

Python API

from scitex_cloud.appmaker import get_prefs, set_prefs
# Read preferences
prefs = get_prefs("writer")  # {"theme": "dark", "font_size": 14}

# Save preferences (merges with existing)
set_prefs("writer", {"theme": "dark", "font_size": 14})

CLI

scitex-cloud app prefs get writer
scitex-cloud app prefs set writer theme=dark font_size=14
scitex-cloud app prefs list
scitex-cloud app prefs delete writer

UI Automation

Programmatic browser control for demos and AI-driven navigation:

from scitex_cloud.appmaker import ui
# Build step sequences
steps = ui.chain(
    ui.navigate_to("/apps/writer/"),
    ui.highlight("#editor", message="Edit here"),
    ui.click_element("#compile-btn"),
)

# Convert to ui_action tool format
action = ui.to_ui_action(steps, delay_ms=500)

Supported actions: navigate, click, highlight, scroll, fill, clear.

Validate & Publish

  1. Validate — scitex-cloud app validate . checks structure, security, manifest, templates, CSS, and dependencies
  2. Submit — scitex-cloud app submit . opens a PR on the scitex-apps registry
  3. Review — Staff reviews the PR (approve/reject/request changes)
  4. Publish — Merge = the app appears in the App Store for all users
You can also right-click your app's sidebar tab and select Submit to App Store to submit directly from the workspace.
