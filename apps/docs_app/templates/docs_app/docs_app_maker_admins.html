External Packages

pip-installable packages can register modules via Python entry points. The registry auto-discovers them at startup: 

# In your package's setup.py or pyproject.toml:
[project.entry-points.scitex_modules]
my_module = "my_package.registry:MODULE_CONFIG"

Where MODULE_CONFIG is a ModuleConfig instance: 

# my_package/registry.py
from apps.workspace_app.registry import ModuleConfig

MODULE_CONFIG = ModuleConfig(
    name="my_module",
    label="My Module",
    app_name="my_module_app",
    icon_fa="fas fa-star",
    partial_template="my_module_app/index_partial.html",
    context_builder="my_package.views.build_context",
    order=100,
    ai_hint="Description for LLM...",
    accent_color="my_module",
)
External module discovery uses Python's importlib.metadata.entry_points(group="scitex_modules"). Install the package and restart SciTeX — the module appears automatically.

Review Queue

The review queue is at /apps/review/ (staff only). Pending submissions appear here after a user clicks “Publish”.

Action Effect
Approve Sets visibility to public, pins the current commit SHA, registers the app in the workspace registry, and notifies the author.
Reject Marks the submission as rejected with a note. The app stays private. Author receives email notification with the rejection reason.
Request Changes Sends the submission back to the author with specific feedback. The author can resubmit after addressing the issues.

Moderation Checklist

When reviewing a submission, check:

  1. Security scan: Automated scan rejects os.system, subprocess, eval, exec, open
  2. Template safety: No overriding protected blocks (content, extra_css, extra_js, title)
  3. Manifest validity: Required fields present, valid SPDX license
  4. CSS scoping: All styles scoped under [data-mode="..."]
  5. No data exfiltration: No external fetch/XHR to third-party domains
  6. README quality: Clear description of what the app does

What Happens on Approval

  1. Submission status → approved
  2. Module visibility → public, is_verified → true
  3. Latest Gitea commit SHA is pinned (pinned_commit)
  4. App is registered into the workspace module registry
  5. Source project app_status updated
  6. Author receives email notification
  7. App appears in the public browse catalog
