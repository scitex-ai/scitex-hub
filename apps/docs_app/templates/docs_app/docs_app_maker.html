Overview

SciTeX workspace modules are self-contained apps that appear as tabs in the workspace. Each module gets its own URL, AJAX-loaded partial, keyboard shortcut, and LLM skill integration.

There are three ways to add modules:

Method For Status
Built-in Core modules (Writer, Scholar, Vis, Hub, Console, Tools) Stable
App Maker User-authored Python modules via web editor WIP
External Package pip-installable modules discovered via entry points WIP

Architecture

Every workspace module consists of these layers:

Layer File Purpose
1. Registry workspace_app/registry.py ModuleConfig entry — single source of truth
2. Views your_app/views.py Full page view + context builder function
3. Templates your_app/templates/ index.html (full page) + index_partial.html (AJAX)
4. URLs config/urls.py path("your/", include(("apps.your_app.urls", "your_app")))
5. Skill your_app/skill.py LLM integration — capabilities, tool prefixes
6. Tests your_app/tests.py ModuleTestMixin validates all layers automatically
The Example App at /example/ is the authoritative reference implementation. Copy its structure for new modules.

ModuleConfig

Every module is defined by a ModuleConfig dataclass in workspace_app/registry.py:

Field Type Description
name str URL slug (e.g., "writer")
label str Display name (e.g., "Writer")
app_name str Django app name (e.g., "writer_app")
icon_fa str FontAwesome class (e.g., "fas fa-pen")
partial_template str AJAX partial template path
context_builder str Dotted path to context function
keyboard_shortcut str Alt+key shortcut (single letter)
order int Tab bar position (lower = leftmost)
status str "stable", "wip", "beta", "deprecated"
default_enabled bool Show in tab bar for new users
ai_hint str Short description for LLM context
accent_color str CSS variable name for module accent

Create a Module

Minimum file structure:

apps/mymodule_app/
├── __init__.py
├── apps.py                      # Django AppConfig
├── views.py                     # index_view + build_mymodule_context
├── urls.py                      # path("", views.index_view, name="index")
├── skill.py                     # LLM skill registration
├── tests.py                     # ModuleTestMixin validation
├── templates/mymodule_app/
│   ├── index.html              # extends "global_base.html"
│   └── index_partial.html      # standalone AJAX partial
└── static/mymodule_app/
    └── css/mymodule.css

Step 1. Add ModuleConfig to workspace_app/registry.py: 

ModuleConfig(
    name="mymodule",
    label="My Module",
    app_name="mymodule_app",
    icon_fa="fas fa-widget",
    partial_template="mymodule_app/index_partial.html",
    context_builder="apps.mymodule_app.views.build_mymodule_context",
    keyboard_shortcut="Y",
    order=75,
    ai_hint="Short description for LLM context",
    accent_color="mymodule",
)

Step 2. Add URL pattern to config/urls.py: 

path("mymodule/", include(("apps.mymodule_app.urls", "mymodule_app"))),

Templates

Each module needs two templates. The full page template extends global_base.html and is served on direct URL access. The partial template is standalone HTML loaded via AJAX when switching tabs (SPA behavior).

index.html — Full page: 

{% verbatim %}{% extends "global_base.html" %}
{% block content %}
    {% include "mymodule_app/index_partial.html" %}
{% endblock %}{% endverbatim %}

index_partial.html — AJAX partial: 

<div class="workspace-project-config" data-mode="mymodule">
    <!-- Your module content here -->
    <h2>My Module</h2>
    <p>Module content...</p>
</div>
The data-mode attribute must match your module's name in the registry. The tab switcher uses this for SPA navigation without page reloads.

Context Builder

The context builder function is called on both full page loads and AJAX partial loads. It must accept request and current_project: 

def build_mymodule_context(request, current_project=None):
    """Called by workspace shell for SPA tab switching."""
    return {
        "current_project": current_project,
        "my_data": MyModel.objects.filter(
            project=current_project
        ) if current_project else [],
    }

def index_view(request):
    """Full page view at /mymodule/."""
    project = get_current_project(request)
    context = build_mymodule_context(request, project)
    return render(request, "mymodule_app/index.html", context)

LLM Skill Registration

Register a Skill so AI assistants understand your module's capabilities. Create skill.py in your app: 

from apps.llm_app.skills import Skill, register
register(
    Skill(
        app_name="mymodule",
        display_name="My Module - Description",
        description="Detailed description for LLM context...",
        capabilities=[
            "Do something useful",
            "Process data",
        ],
        page_patterns=["/mymodule/"],
        url_prefix="/mymodule/",
        module_description="One-line summary.",
    )
)

Testing

ModuleTestMixin automatically validates all module layers. Create tests.py: 

from django.test import TestCase
from apps.workspace_app.test_mixin import ModuleTestMixin

class MyModuleTest(ModuleTestMixin, TestCase):
    module_name = "mymodule"

This validates:

Check What it verifies
test_module_registered Module exists in registry
test_partial_template_exists AJAX partial template file exists
test_icon_registered Has FontAwesome or SVG icon
test_context_builder_importable Context builder function is callable
test_ai_hint_defined LLM hint text is non-empty
test_accent_color_css_exists CSS variable --module-accent-{name} defined
test_skill_registered Skill exists in LLM registry

Apps Catalog

The Apps catalog is a catalog of all workspace modules. Users can browse, install, star, review, and reorder modules.

Feature Description
Install / Uninstall Add or remove modules from your tab bar
Enable / Disable Toggle module visibility (built-ins cannot be uninstalled, only disabled)
Reorder Drag to reorder tab positions (syncs across tab bar and apps catalog)
Star Bookmark favorite modules
Review Rate (1–5) and comment on modules
Publish Submit user modules for public listing (requires admin review)

Built-in modules are auto-seeded into the apps catalog on first visit. Categories: writing, visualization, data, analysis, reference, utility.

User Modules (App Maker)

The App Maker lets authenticated users create custom modules from Python source code directly in the browser.

Field Description
slug Unique identifier per user
label Display name
source_code Python source (validated for security)
icon FontAwesome icon class
category writing, visualization, data, analysis, reference, utility
visibility private, group (shared with project), public
version Semantic version string
dependencies JSON list of required packages

API endpoints:

Endpoint Method Description
/appmaker/api/create/ POST Create a new module
/appmaker/api/<slug>/update/ POST Update module source and metadata
/appmaker/api/<slug>/run/ POST Execute module (sandboxed)
/appmaker/api/<slug>/delete/ POST Soft-delete module
User-submitted source code is scanned for forbidden patterns (os.system, subprocess, eval, exec, open, etc.) before execution.

External Packages

pip-installable packages can register modules via Python entry points. The registry auto-discovers them at startup: 

# In your package's setup.py or pyproject.toml:
[project.entry-points.scitex_modules]
my_module = "my_package.registry:MODULE_CONFIG"

Where MODULE_CONFIG is a ModuleConfig instance: 

# my_package/registry.py
from apps.workspace_app.registry import ModuleConfig

MODULE_CONFIG = ModuleConfig(
    name="my_module",
    label="My Module",
    app_name="my_module_app",
    icon_fa="fas fa-star",
    partial_template="my_module_app/index_partial.html",
    context_builder="my_package.views.build_context",
    order=100,
    ai_hint="Description for LLM...",
    accent_color="my_module",
)
External module discovery uses Python's importlib.metadata.entry_points(group="scitex_modules"). Install the package and restart SciTeX — the module appears automatically.
