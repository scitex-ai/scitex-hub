Self-Hosting Guide

Docker + Apptainer

What You Get

SciTeX Cloud is a self-hostable research platform. One make start gives you a full Django application with:

Module Description
Scholar Literature search across CrossRef, PubMed, arXiv, and OpenAlex. BibTeX management and citation tracking.
Writer LaTeX manuscript editor with BibTeX integration, figure/table management, and IMRAD templates.
Vis Data visualization and interactive figure editing.
Console Web-based terminal for running Python and Bash in isolated Apptainer containers via SLURM.
Hub Project file browser with GitHub-style /username/project/ URLs, backed by Gitea.
Research Tools Statistics, PDF manipulation, citation scraping, QR generation, and more.
MCP Server 200+ tools for AI agents (Claude, Cursor, etc.) to search literature, manage citations, generate figures, and run statistics.

Architecture

Docker Compose orchestrates all services. Only one environment (dev/staging/prod) runs at a time.

Service Image Role
Django scitex-cloud-dev-django Web application, REST API, WebSocket (Daphne ASGI in prod)
PostgreSQL postgres:15-alpine Primary database for all application data
PgBouncer edoburu/pgbouncer Connection pooling proxy (production)
Redis redis:7-alpine Cache, Celery broker, WebSocket channel layer
Celery Worker Same as Django Async tasks: AI, search, compute, vis queues (concurrency=4)
Celery Beat Same as Django Periodic task scheduler (django_celery_beat)
Flower Same as Django Celery monitoring dashboard (dev only)
Gitea gitea/gitea:latest Self-hosted Git server for project repositories
Nginx nginx Reverse proxy, static files, gzip (production)
Umami ghcr.io/umami-software Privacy-focused analytics (no external tracking)

Optional local databases for offline paper search:

Database Description
CrossRef Local 167M+ papers in a local SQLite database. Fast, offline metadata search with citation graph analysis.
OpenAlex Local 284M+ scholarly works with full-text search, abstracts, and impact factors.

Quick Start

Three commands to get everything running:

git clone https://github.com/ywatanabe1989/scitex-cloud.git
cd scitex-cloud
make start
Access at localhost:8000. Test user: test-user / Password123!

Development Setup

1. Clone and configure 

git clone https://github.com/ywatanabe1989/scitex-cloud.git
cd scitex-cloud
cp deployment/docker/envs/.env.example deployment/docker/docker_dev/.env

2. Set secret key (edit .env) 

SCITEX_CLOUD_DJANGO_SECRET_KEY=$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')
SCITEX_CLOUD_POSTGRES_PASSWORD=your-dev-password

3. Start services 

make ENV=dev start
make status
Development mode includes hot-reload for Python, TypeScript, and templates. Changes reflect immediately without rebuilding.

Production Setup

For deploying on a home server, NAS, or VPS:

1. Prepare the host 

# Create scitex system user (UID 1000)
sudo deployment/host-setup/scripts/create-scitex-user.sh

# Validate host readiness
make ENV=prod check-host

2. Create production environment 

cp deployment/docker/envs/.env.example deployment/docker/docker_prod/.env

3. Configure for production (edit .env) 

DEBUG=False
SCITEX_CLOUD_DOMAIN=scitex.example.com
SCITEX_CLOUD_SITE_URL=https://scitex.example.com
SCITEX_CLOUD_ENABLE_SSL_REDIRECT=true
SCITEX_CLOUD_DJANGO_SECRET_KEY=your-strong-secret-key

4. Build and start 

make ENV=prod build
make ENV=prod start
make status
Production uses Daphne (ASGI) behind Nginx, with PgBouncer for database connection pooling. Only one environment runs at a time — starting prod stops dev automatically.

Ports & Services

Default port assignments for development:

Port Service Notes
8000 Django Main web application
5433 PostgreSQL Database (mapped from 5432)
6379 Redis Cache and message broker
3001 Gitea Git server HTTP (mapped from 3000)
3300 Umami Analytics dashboard
5555 Flower Celery monitoring (dev only)
2200 SSH Gateway SSH access to containers
5678 Debugpy Python debugger (dev only)
5173 Vite HMR TypeScript hot-reload (dev only)
In production, only the SSH gateway port (2200) is exposed directly. HTTP traffic goes through Nginx and optionally a Cloudflare Tunnel.

Apptainer Containers

The Console terminal runs user code in isolated Apptainer (formerly Singularity) containers, scheduled via SLURM.

Pre-built image includes:

Category Contents
Python Python 3.11 + SciTeX ecosystem (scitex, figrecipe, scitex-writer, crossref-local, openalex-local)
AI CLI Node.js 20 + Claude Code, Codex, Gemini CLI, agents
LaTeX Full texlive suite for manuscript compilation
Dev Tools ipdb, black, flake8, Microsoft core fonts

Build from definition file: 

cd deployment/singularity
apptainer build scitex-cloud-shared-v0.1.0.sif scitex-cloud-shared-v0.1.0.def

Test with writable sandbox: 

apptainer exec --fakeroot --writable current-sandbox/ python3 -c "import scitex; print(scitex.__version__)"

Host Setup (Production)

For production on a NAS or server, the host machine needs some configuration. Non-destructive validation scripts check readiness: 

# Validate host (non-destructive checks)
deployment/host-setup/checks/check-slurm.sh       # SLURM daemon & partitions
deployment/host-setup/checks/check-users.sh        # scitex user (UID 1000)
deployment/host-setup/checks/check-apptainer.sh    # Apptainer availability
deployment/host-setup/checks/check-services.sh     # Service health

Setup scripts (require sudo): 

# Create scitex system user
sudo deployment/host-setup/scripts/create-scitex-user.sh

# Restart SLURM for new user
sudo deployment/host-setup/scripts/restart-slurm-for-new-user.sh

# Test terminal connectivity
deployment/host-setup/scripts/test-terminal-connection.sh

CLI-Only Install

Use the Python toolkit and MCP server without Docker:

pip install scitex              # Python toolkit
pip install scitex[mcp]         # Toolkit + MCP server
pip install scitex[all]         # Everything

scitex --version
scitex --help

MCP Server for AI Agents

Connect AI assistants (Claude, Cursor, etc.) to your SciTeX instance:

scitex mcp start                # Start MCP server
scitex mcp doctor               # Diagnose setup
scitex mcp installation          # Client config
See MCP Tools Documentation for the full list of 200+ available tools.
