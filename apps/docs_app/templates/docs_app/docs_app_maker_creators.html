App Maker: For Creators

WIP

Overview

SciTeX workspace modules are self-contained apps that appear as tabs in the workspace. Each module gets its own URL, AJAX-loaded partial, keyboard shortcut, and LLM skill integration.

There are three ways to add modules:

Method For Status
Built-in Core modules (Writer, Scholar, Vis, Hub, Console, Tools) Stable
App Maker User-authored Python modules via web editor WIP
External Package pip-installable modules discovered via entry points WIP

Architecture

Every workspace module consists of these layers:

Layer File Purpose
1. Registry workspace_app/registry.py ModuleConfig entry — single source of truth
2. Views your_app/views.py Full page view + context builder function
3. Templates your_app/templates/ index.html (full page) + index_partial.html (AJAX)
4. URLs config/urls.py path("your/", include(("apps.your_app.urls", "your_app")))
5. Skill your_app/skill.py LLM integration — capabilities, tool prefixes
6. Tests your_app/tests.py ModuleTestMixin validates all layers automatically
The Example App at /example/ is the authoritative reference implementation. Copy its structure for new modules.

ModuleConfig

Every module is defined by a ModuleConfig dataclass in workspace_app/registry.py:

Field Type Description
name str URL slug (e.g., "writer")
label str Display name (e.g., "Writer")
app_name str Django app name (e.g., "writer_app")
icon_fa str FontAwesome class (e.g., "fas fa-pen")
partial_template str AJAX partial template path
context_builder str Dotted path to context function
keyboard_shortcut str Alt+key shortcut (single letter)
order int Tab bar position (lower = leftmost)
status str "stable", "wip", "beta", "deprecated"
default_enabled bool Show in tab bar for new users
ai_hint str Short description for LLM context

Create a Module

Minimum file structure:

apps/mymodule_app/
├── __init__.py
├── apps.py                      # Django AppConfig
├── views.py                     # index_view + build_mymodule_context
├── urls.py                      # path("", views.index_view, name="index")
├── skill.py                     # LLM skill registration
├── tests.py                     # ModuleTestMixin validation
├── templates/mymodule_app/
│   ├── index.html              # extends "global_base.html"
│   └── index_partial.html      # standalone AJAX partial
└── static/mymodule_app/
    └── css/mymodule.css

Step 1. Add ModuleConfig to workspace_app/registry.py: 

ModuleConfig(
    name="mymodule",
    label="My Module",
    app_name="mymodule_app",
    icon_fa="fas fa-widget",
    partial_template="mymodule_app/index_partial.html",
    context_builder="apps.mymodule_app.views.build_mymodule_context",
    keyboard_shortcut="Y",
    order=75,
    ai_hint="Short description for LLM context",
    accent_color="mymodule",
)

Step 2. Add URL pattern to config/urls.py: 

path("mymodule/", include(("apps.mymodule_app.urls", "mymodule_app"))),

Templates

Each module needs two templates. The full page template extends global_base.html. The partial template is standalone HTML loaded via AJAX.

index.html — Full page: 

{% verbatim %}{% extends "global_base.html" %}
{% block content %}
    {% include "mymodule_app/index_partial.html" %}
{% endblock %}{% endverbatim %}

index_partial.html — AJAX partial: 

<div class="workspace-project-config" data-mode="mymodule">
    <!-- Your module content here -->
</div>
The data-mode attribute must match your module's name in the registry.

Context Builder

The context builder function is called on both full page loads and AJAX partial loads:

def build_mymodule_context(request, current_project=None):
    """Called by workspace shell for SPA tab switching."""
    return {
        "current_project": current_project,
        "my_data": MyModel.objects.filter(
            project=current_project
        ) if current_project else [],
    }

def index_view(request):
    """Full page view at /mymodule/."""
    project = get_current_project(request)
    context = build_mymodule_context(request, project)
    return render(request, "mymodule_app/index.html", context)

LLM Skill Registration

Register a Skill so AI assistants understand your module's capabilities:

from apps.llm_app.skills import Skill, register
register(
    Skill(
        app_name="mymodule",
        display_name="My Module - Description",
        description="Detailed description for LLM context...",
        capabilities=["Do something useful", "Process data"],
        page_patterns=["/mymodule/"],
        url_prefix="/mymodule/",
        module_description="One-line summary.",
    )
)

manifest.json

Every app must include a manifest.json at the project root: 

{
    "name": "my_awesome_app",
    "label": "My Awesome App",
    "version": "0.1.0",
    "description": "Short description of what the app does.",
    "icon": "fas fa-rocket",
    "license": "MIT",
    "capabilities": ["data-visualization", "export"],
    "min_scitex_version": "0.6.0",
    "author": "Your Name",
    "homepage": "https://example.com"
}
Field Required Description
name Yes Module name (must end with _app)
label No Display label in tab bar
version Yes Semantic version
description Yes Short description (max 200 chars)
icon No FontAwesome class (default: fas fa-puzzle-piece)
license Yes SPDX identifier (e.g. MIT, Apache-2.0, AGPL-3.0)
capabilities No List of capability tags
min_scitex_version No Minimum compatible SciTeX version

CSS Variables & Theming

Use SciTeX CSS variables for consistent theming. Your CSS must be scoped under [data-mode="yourmodule"] to prevent style leaks: 

/* yourmodule_app/static/yourmodule_app/css/yourmodule.css */
[data-mode="yourmodule"] {
    --app-accent: var(--module-accent-yourmodule, #4a90d9);
}
[data-mode="yourmodule"] .my-card {
    background: var(--bg-primary);
    border: 1px solid var(--border-subtle);
    color: var(--text-primary);
}

Available theme variables:

Variable Description
--bg-primary Main background color
--bg-secondary Secondary/card background
--text-primary Main text color
--text-muted Subdued text color
--border-subtle Subtle border color
--accent Global accent color

Shared UI Components

The workspace frame provides reusable components. All styles are auto-loaded — just add the HTML markup in your templates.

Resizer (Split Panels)

Drag-resize and collapse between two panels:

<!-- Horizontal: sidebar | content -->
<div class="my-sidebar">...</div>
<div class="h-resizer" data-h-resizer
     data-left=".my-sidebar"
     data-right=".my-content"
     data-most-left
     data-threshold="40"
     data-in-app></div>
<div class="my-content">...</div>
Attribute Description
data-h-resizer Horizontal (left/right). Use data-v-resizer for vertical
data-left / data-right CSS selectors for adjacent panels
data-most-left / data-most-right Which side collapses when dragged below threshold
data-threshold Collapse threshold in pixels (default: 40)
data-in-app Required for in-app resizers

Selector Nav (Mode Switcher)

Vertical icon+label navigation strip for switching views within your module:

<nav class="selector-nav" id="myapp-mode-selector" data-indicator="right">
    <button class="selector-nav-item active" onclick="switchMode('chart')">
        <i class="fas fa-chart-bar"></i>
        <span class="selector-nav-label">Chart</span>
    </button>
    <button class="selector-nav-item" onclick="switchMode('table')">
        <i class="fas fa-table"></i>
        <span class="selector-nav-label">Table</span>
    </button>
</nav>

Set data-indicator="right" for an active accent bar on the right edge. Toggle .active class on .selector-nav-item via JavaScript.

CSS files: components/resizer.css and components/selector-nav.css. Both are loaded globally — no extra imports needed.

Publishing Workflow

  1. Scaffold: scitex-cloud app init . — creates all boilerplate
  2. Develop: Edit templates, views, and CSS in your project
  3. Validate: scitex-cloud app validate . — checks structure and security
  4. Publish: scitex-cloud app publish . or click “Publish” on the detail page
  5. Review: Admin reviews source code and approves/rejects
  6. Live: Approved app appears in the public Apps catalog
Source code is automatically scanned for forbidden patterns (os.system, subprocess, eval, exec) before submission. The commit SHA is pinned on approval for reproducibility.

Template Rules

User app templates are loaded from project directories with the following constraints:

  • Templates must not override protected blocks: extra_css, extra_js, content, title
  • Templates are standalone HTML fragments (AJAX partials), not full pages
  • The root element must have data-mode="yourmodule"
  • No {% verbatim %} {% extends %} {% endverbatim %} or {% verbatim %} {% load %} {% endverbatim %} tags allowed

Testing

ModuleTestMixin automatically validates all module layers: 

from django.test import TestCase
from apps.workspace_app.test_mixin import ModuleTestMixin

class MyModuleTest(ModuleTestMixin, TestCase):
    module_name = "mymodule"

This validates:

Check What it verifies
test_module_registered Module exists in registry
test_partial_template_exists AJAX partial template file exists
test_icon_registered Has FontAwesome or SVG icon
test_context_builder_importable Context builder function is callable
test_ai_hint_defined LLM hint text is non-empty
test_accent_color_css_exists CSS variable --module-accent-{name} defined
test_skill_registered Skill exists in LLM registry
